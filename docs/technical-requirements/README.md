# Корпус технічних вимог

`edition-39.json` отримано з PDF, наданого для цієї роботи:
`39-MIS-Tehnichni-vymogy-v-redaktsii-nakazu-NSZU-464-vid-25.08.2026.pdf`.
Метадані містять SHA-256 оригінального PDF, редакцію, наказ і 218 фізичних сторінок.
Оригінальний PDF зберігається окремо від Git; JSON містить текст 1629 нумерованих
пунктів, а не модельний переказ. Сторінки є PDF-сторінками, включно з титульною.

Пункт вибирається разом із усіма підпунктами за префіксом номера. Наприклад,
`3.5.1.3` включає `3.5.1.3.1`, але не включає `3.5.1.4`.
Посилання на інші пункти або зовнішні специфікації API не підміняються здогадками:
якщо потрібного тексту/коду немає, потрібна додаткова перевірка.

## Оновлення редакції

1. Отримати затверджений PDF та перевірити, що його можна публікувати у текстовому вигляді.
2. Визначити фізичну сторінку початку основного тексту, без змісту й визначень.
3. У локальному середовищі з `pypdf` виконати:

   ```sh
   python scripts/requirements/build-corpus.py input.pdf docs/technical-requirements/edition-40.json \
     --edition 40 --order 'Номер і дата затвердженого наказу' --start-page 9
   ```

4. Перевірити результати за оригінальним PDF, зокрема багатосторінкові пункти,
   списки, таблиці та межі сусідніх пунктів. Parser розрахований на відступи цього
   PDF; інший layout потребує адаптації. Дублікати номерів зупиняють імпорт.
5. У `azure-requirements-review.php` змінити `REQUIREMENTS_CORPUS`; оновити перевірки
   редакції та контрольних пунктів у `azure-requirements-review-test.php`.
6. Провести review змін корпусу та перевірок через PR. Злиття оновлення змінює
   fingerprint і дає змогу повторити аналіз старого PR із новими вимогами вручну.

Corpus завантажується лише з довіреного `main`; PR не може підмінити вимоги у
привілейованому запуску. Кодовий reviewer пропускає цей згенерований текст,
а requirements checks перевіряють схему, унікальність, сторінки та контрольні межі.

Текст вимог та код передаються моделі як дані. Результат не є сертифікацією МІС,
юридичним висновком або заміною перевірки інтеграції з eHealth.
